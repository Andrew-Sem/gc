# Запускаемый продукт

Готовый результат — не библиотека и не только зелёные таблицы. После реализации человек
заполняет `.env`, запускает один бинарник, открывает браузер и проходит все шесть сценариев без
ручных вызовов внутренних функций.

## Официальный способ запуска

```bash
just build
./gc
```

Один процесс держит всё: HTTP-сервер админки и вебхуков, журнал и очередь в SQLite,
планировщик двух wake-up и исполнение задач, включая запуск Codex и работу с `git`.
Внешних сервисов нет. Docker остаётся необязательным способом доставки, а не условием запуска.

`just up` собирает и запускает тот же бинарник в контейнере с примонтированными томами для базы
и `CODEX_HOME`. Официальная топология от этого не меняется: внутри контейнера тот же один процесс.

Публичный HTTPS нужен только для приёма вебхуков. Без него система работает, но экран
«почему PR висит» обновляется лишь раз в шесть часов.

## Переменные окружения

Репозиторий содержит `.env.example` без секретов. Старт валидирует env до открытия порта и
печатает одну понятную ошибку на каждое отсутствующее или неверное значение.

Обязательные:

- `GITHUB_TOKEN` — PAT с правами на repo, checks и branch protection;
- `GITHUB_WEBHOOK_SECRET` — секрет подписи вебхуков;
- `OPENAI_API_KEY` — ключ для Codex;
- `PUBLIC_URL` — внешний origin, по которому GitHub шлёт вебхуки;
- `DB_PATH`, `CODEX_HOME`, `WORKSPACE_ROOT` — пути с сохранением между рестартами;
- `LISTEN_ADDR` — адрес и порт HTTP.

Секретные значения не попадают в журнал, снимки задач, HTML, ответы health и логи. Логи
пишут имя переменной, но никогда её значение.

## Админка

Админка — server-rendered HTML. JavaScript ограничен htmx: он подменяет фрагменты страницы
и не держит собственного состояния. Дизайн намеренно минимальный.

Через браузер доступны:

1. подключение репозитория формой `owner/name` и отключение кнопкой;
2. список подключённых репозиториев;
3. настройки инстанса: model, reasoning, prompt и optional OpenAI Base URL;
4. настройки репозитория: cadence, open PR limit и close age;
5. живой экран «почему PR висит» с причиной и следующим действием.

Формы имеют label, валидацию, а также состояния успеха и ошибки. После сохранения и после
нового вебхука данные обновляются подменой фрагмента, без перезагрузки страницы руками.

Аутентификации нет: инстанс однопользовательский. Поэтому админка не должна быть открыта
в интернет. Наружу публикуется только путь вебхука; на остальные пути оператор ставит
ограничение по адресу или обратный прокси со своей защитой. Это записанное ограничение
развёртывания, а не то, что проверяют таблицы.

## Очередь задач

Очередь живёт в SQLite рядом с журналом. Задача берётся под аренду, продлевается до половины
срока и переживает рестарт. Истёкшая аренда снова доступна; один task не порождает двух
семантических результатов. Повтор внешнего вызова после падения допустим только с тем же
стабильным idempotency key либо после сверки с внешней системой.

Запись задачи и запись фактов, которые её породили, происходят в одной транзакции: журнал и
очередь не расходятся. На `SIGTERM` процесс перестаёт брать новые задачи и завершает либо
безопасно освобождает текущую аренду. На временную ошибку — ограниченный backoff с jitter.

## Запуск агента

Codex запускается как подпроцесс. Он получает только явный allowlist безопасных переменных
окружения плюс `CODEX_HOME` и ключ модели; webhook secret и токен GitHub ему не наследуются.
Одновременные заходы агента по одной паре репозиторий/задача сериализуются файловой блокировкой
с heartbeat и восстановлением зависшей блокировки.

Контракты handoff типизированы и передают значения явно:

- подготовка рабочей копии: каталог, base branch и новая branch;
- запуск Codex: исход и расход токенов;
- commit/push: branch и head SHA;
- создание PR: repo, base, head branch, title/body и стабильный idempotency key;
- результат: number, branch и head SHA для отчёта.

Пустое изменение не создаёт PR и журналируется как завершённый заход агента без выдуманного
номера. Повтор задачи использует ту же стабильную ветку и безопасно продолжает с существующего
remote head; push огорожен ожидаемым remote head, а не создаёт новую ветку или второй PR.

Временные рабочие копии живут отдельно от `CODEX_HOME` и удаляются после задачи.

## Health и persistence

Health endpoints не раскрывают секретов и различают liveness и readiness. Readiness означает:
env валиден, база открыта и мигрирована, `git` и `codex` доступны.

После рестарта сохраняются журнал, задачи, настройки, список подключённых репозиториев и
`CODEX_HOME`.

## Обязательный реальный smoke

Задача реализации не завершена без успешного smoke с настоящими credentials. Smoke работает
только с явно выделенным disposable GitHub repository и имеет право создавать, мержить и
закрывать PR. До запуска он сверяет numeric repository ID, owner/name и disposable marker.

```bash
just smoke
```

Smoke проходит через настоящие HTTP boundary и подпроцессы:

1. чистый старт и health;
2. подключение репозитория формой и появление его в списке;
3. реальный запуск Codex и минимальный вызов модели, включая configured OpenAI Base URL либо
   официальный endpoint при пустом значении;
4. реальные clone, изменение, commit, push и создание PR;
5. подписанный вебхук через публичный путь;
6. required-check lookup, включая чтение защиты ветки, и живой экран «почему PR висит»;
7. запуск production и sweep тиков вручную, без ожидания часов;
8. merge и закрытие по возрасту;
9. рестарт процесса с сохранением состояния;
10. отключение репозитория и прекращение тиков по нему.

Тики и мерж в smoke запускаются HTTP-путями админки, а не вызовом внутренних функций.

Если credentials, публичный HTTPS или disposable repository недоступны, задача реализации
заблокирована и не может считаться завершённой.
