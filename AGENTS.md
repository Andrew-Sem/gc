# Garbage Collector

Event-driven control plane над жизненным циклом PR: приём фактов из GitHub, журнал событий,
слой решений, эффекты.

**Прежде чем что-то делать, прочитай:**

- `specs/use-cases.md` — что система делает, шесть сценариев
- `specs/glossary.md` — единый язык, синонимов не заводим
- `specs/facts.md` — одиннадцать фактов и их границы
- `docs/architecture.md` — из чего собрана и почему именно так

## Команды

```bash
just check   # петля обратной связи: типы, затем спеки
just spec    # только исполняемые спеки домена
just types   # только типы
just dev     # дев-сервер админки
just lint    # Biome, harness-linter, границы слоёв FSD (steiger)
```

`just lint-fix` чинит безопасные замечания Biome и харнесс-политики. Границы FSD автофиксу
не поддаются — их правят руками.

`just spec` — петля после каждой правки, и она обязана оставаться в пределах примерно пяти
секунд. Стала медленнее — это баг, и чинится он до добавления новых таблиц.

## Два режима работы. Не смешивай их

**Режим 1 — авторинг спек.** Вместе с человеком описываем поведение: правим `specs/`,
`packages/domain/src/contract.ts` и таблицы `*.spec.ts`. Реализацию в этом режиме не пишем.

**Режим 2 — реализация.** Отдельная чистая сессия. Задача одна: сделать зелёными уже
написанные таблицы.

В режиме 2 **запрещено менять**:

- `packages/domain/src/contract.ts`
- любые `*.spec.ts` и `fixtures.ts`
- `packages/domain/src/framework/`
- всё в `specs/`, конфиги, `freeze-manifest.json`

Если таблица кажется неверной — **не правь её**. Остановись и скажи человеку.

Требования берутся только из `specs/`, контракта и таблиц. Если требование неясно или
таблицы противоречат друг другу — остановись и спроси, не придумывай своё толкование.

## Домен

```
packages/domain/src/
  contract.ts        факты, команды, ошибки — словарь домена
  decider.ts         decide, evolve, initialState — реализация
  fixtures.ts        заготовки для таблиц
  *.spec.ts          исполняемые таблицы given/when/then
  framework/         раннер таблиц, взят из Nucex
```

`packages/domain` не знает ни про Convex, ни про GitHub. Его импортируют и функции Convex, и
спеки — поэтому спеки проверяют ровно тот код, который работает в проде.

**Форма состояния (`GcState`) — внутренняя.** Меняй её свободно под задачу. Текущая скроена
под одно правило `admission` и для остальных правил её надо переделывать, а не достраивать
сбоку.

Семантика решений:

- дублирующая или неприменимая команда — это `{ ok: true, events: [] }`, а не ошибка;
- отклонённая команда — `{ ok: false, error: … }`; `decide` не бросает исключений;
- порядок событий нормативен — таблицы сравнивают списки целиком.

`admission` реализован как эталон wiring'а. Смотри на него, когда непонятно, как принято
оформлять; форму состояния не копируй.

## Заморозка

`packages/domain/freeze-manifest.json` хранит SHA-256 замороженных файлов. Проверяет их
`freeze.spec.ts` — обычная таблица, падает вместе с остальными.

Две части. `shared` — контракт, фикстуры и раннер: их видят все слайсы. `slices` — таблицы
конкретного слайса. Статус `domain-approved` означает, что поведение утверждено человеком.

Красный тест заморозки в **режиме реализации** значит, что ты тронул запрещённое. Верни файл,
не правь манифест.

`just freeze-on` дополнительно запрещает правку этих файлов на уровне харнесса, но deny-правила
защищают только от случайной правки — гарантией остаются `freeze.spec.ts` и ревью диффа.

Авторинг нового слайса меняет контракт и, значит, ломает `shared`. Это нормально: в режиме
авторинга человек пересчитывает хеши и заново утверждает. Таблицы уже утверждённых слайсов при
этом должны остаться зелёными — если они покраснели, изменение контракта поменяло поведение, и
это надо обсудить, а не замазать.

## UI

Компоненты берём из **shadcn/ui**, не пишем свои с нуля. Перед тем как верстать элемент,
проверь, есть ли готовый компонент.

```bash
just ui-add button          # один компонент
just ui-add dialog dropdown-menu
```

Компоненты уезжают в `packages/ui/src/components` и импортируются как
`@workspace/ui/components/<name>`. Приложение их не копирует к себе.

`packages/ui/src/components` исключён из Biome: это сгенерированный код, переформатировать
его нельзя, иначе следующий `shadcn add` даст конфликт.

## Структура фронтенда

Feature-Sliced Design. Слои сверху вниз, импорт разрешён только вниз:

```
apps/web/src/
  app/       композиция приложения, провайдеры, entry
  pages/     экраны
  features/  пользовательские сценарии
  entities/  доменные сущности
  shared/    переиспользуемое без привязки к домену
```

Правила, которые проверяет `steiger`:

- слой импортирует только слои ниже себя, никогда выше и никогда соседний срез напрямую;
- у среза есть публичный API — `index.ts`, всё остальное наружу не торчит;
- внутри среза сегменты `ui`, `model`, `api`, `lib`.

Слои создаются по мере надобности. Пустых `features/` и `entities/` заранее не заводим.
