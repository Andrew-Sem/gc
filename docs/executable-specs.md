# Что покрывается таблицами

Справка, а не инструкция. Правила для агентов живут в `AGENTS.md`.

## Граница проходит не там, где кажется

Первая мысль — «домен покрываем таблицами, обвязку описываем текстом». Она неверная.
Настоящая граница: **чистое преобразование против ввода-вывода**. Чистого в обвязке гораздо
больше, чем кажется.

| Кусок | Чем проверяется |
|---|---|
| Правило admission | таблицы |
| Правило merge-gate | таблицы |
| Разбор вебхука в команду | таблицы |
| События в эффекты | таблицы |
| Журнал в модель экрана | таблицы |
| Расписание кронов | таблицы — читаем декларацию |
| Монтирование роутов | таблицы — читаем роутер |
| Опции запуска Codex | таблицы — читаем собранное значение |
| Экран «почему PR висит» | таблицами — см. ниже |
| Остальная вёрстка | глазами |
| Наличие `git` в контейнере | первым запуском |

## Для экрана «почему PR висит» граница сдвигается

Сам компонент — тоже чистая функция: `PrStatusLine[]` на входе, разметка на выходе. Значит
проверяем и его: вердикт даёт видимый текст причины, часы до закрытия показаны верно.

Делать это будем **после** того, как позеленеют текущие таблицы: тогда появится отдельный
авторинг-слайс `why-stuck-screen` с таблицами через testing-library. Остальной интерфейс —
формы настроек, подключение репозитория — по-прежнему глазами.

## Правило формы: конфигурация — это значение

Из него следует всё остальное.

Зашитая прямо в вызов настройка непроверяема:

```ts
// проверить нечем
await codex.startThread({ sandboxMode: "workspace-write", ... })
```

Вынесенная в чистую функцию — проверяема таблицей:

```ts
// таблица поймает неверный sandboxMode
await codex.startThread(codexOptions(settings))
```

Ровно та же логика применима к кронам, роутам и любой другой конфигурации. Если решение
выражено значением, его можно сравнить с ожидаемым.

Цена: агенту нельзя писать конфигурацию инлайном. Форма навязана, и это осознанно.

## Чего мы не делаем

**Не гоняем фейковое время, чтобы дождаться срабатывания крона.** Такой тест проверяет
планировщик Convex, а не наш код: он медленный, хрупкий, и красным ничего полезного не
сообщает. Достаточно прочитать декларацию и сравнить: имя, интервал, куда ведёт.

**Не дублируем проверку на разных уровнях.** Если поведение закрыто таблицей домена,
интеграционный тест поверх него не нужен.
