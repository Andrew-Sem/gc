# Разрывы, обнаруженные после первичных спек

Этот документ фиксирует, что пришлось обнаружить уже после первой реализации. Это не новый
источник доменных правил: актуальные нормы находятся в `specs/` и архитектурных документах.
Цель ретроспективы — не смешивать три разных причины переделок:

- **Пробел спецификации** — поведение или boundary не были определены, поэтому несколько
  несовместимых реализаций формально выглядели допустимыми.
- **Дефект реализации** — правило уже следовало из утверждённой модели, но production wiring его
  нарушил.
- **Пробел проверки** — тест или smoke доказывал не тот seam, был слишком слабым либо требовал
  недоступный/неверный контракт.

## Пробелы спецификации

| Разрыв | Последствие | Как закрыт новыми спеками |
|---|---|---|
| Необязательный OpenAI Base URL отсутствовал в tenant settings и task semantics. | Gateway мог читаться поздно из mutable storage, не дойти до Codex или незаметно поменять уже одобренный запуск. | Base URL определён как boundary setting: normalized absolute HTTP(S), без credentials/query/fragment; пустое значение означает официальный endpoint; due-значение сохраняется в immutable `RunAgent` snapshot и передаётся Codex, но не журналируется. |
| GitHub onboarding был описан как ручное создание App на tenant и ввод App ID, installation ID, private key и webhook secret. | UX требовал от каждого владельца GitHub administration и обращение с критичными secrets; tenant фактически становился installation, а deployment не имел единой security boundary. | На deployment существует один operator-registered shared GitHub App. Owner видит одну same-origin ссылку `Подключить GitHub`; App credentials задаются только operator env. |
| Промежуточная попытка GitHub App Manifest создавала отдельный App на tenant. | Manifest улучшал форму, но сохранял неверную per-tenant модель, размножал private keys/webhook secrets и добавлял conversion/install callbacks вместо устранения credentials из tenant plane. | Manifest flow удалён из нормативной модели. App bootstrap отделён от tenant onboarding: оператор регистрирует shared App один раз, tenants устанавливают его. |
| Не было нормативного доказательства, что callback installation принадлежит вошедшему GitHub user. | Одних session-bound state и App-JWT lookup недостаточно: `installation_id` из query остаётся недоверенным, а App lookup доказывает существование установки, не участие текущего user. | После setup callback обязателен отдельный GitHub App OAuth web flow со свежим one-time state и PKCE. OAuth callback требует ту же Better Auth session и наличие installation в полностью пагинированном `/user/installations`. |
| `request_oauth_on_install` и разделение install/OAuth state не были определены. | GitHub мог начать неявный OAuth во время install, смешав две callback-модели и усложнив replay/session binding. | `request_oauth_on_install` выключен; install state и OAuth state независимы, короткоживущи, одноразовы и связаны с subject+tenant/session. |
| App permissions не включали явно `administration: read`. | Чтение branch protection/required checks могло получать 403, а merge-gate превращался в постоянный `LookupIncomplete`. | Нормативный permission set включает administration read, checks read, contents write, metadata read и pull_requests write; smoke обязан доказать branch-protection lookup. |
| Callback trust, session continuity, expiry, replay и atomicity были недоопределены. | Callback можно было обработать с другой session, повторить с новым эффектом, частично записать installation без всех repositories либо связать одну installation с двумя tenants. После успешного OAuth exchange сетевой сбой мог потребовать повторно использовать уже одноразовый code. | Оба callback требуют ту же Better Auth session; state one-time/TTL для новой попытки; после exchange сохраняются code hash и зашифрованная временная authorization, поэтому exact recovery retry продолжает flow без второго exchange; bind уникален; `GitHubAppConnected` и все `RepositoryConnected` атомарны и идемпотентны. |
| Не была определена судьба временного GitHub user authorization. | User token мог стать долгоживущим лишним credential и попасть в worker или storage. | User authorization используется только для onboarding proof и после финализации удаляется либо отзывается. Worker её никогда не получает. |
| Webhook secret считался tenant secret и выбирался по installation до signature verification. | Неподписанный payload влиял на secret/tenant lookup; tenant storage содержал глобально опасные credentials. | У shared App один global webhook secret. Signature проверяется до tenant resolution, dedupe и parser; installation ID используется только после проверки подписанного body. |
| Не были определены operator bootstrap, rotation и App lifecycle. | Непонятно, как впервые создать App, сменить private key/client secret/webhook secret, обработать suspension/deletion или изменение selected repositories. | Env contract задаёт `GITHUB_APP_ID`, `GITHUB_APP_CLIENT_ID`, `GITHUB_APP_CLIENT_SECRET`, `GITHUB_APP_PRIVATE_KEY`, `GITHUB_APP_SLUG`, `GITHUB_APP_WEBHOOK_SECRET`; rotation является operator operation; installation lifecycle и repository-selection events запускают reconciliation, removal меняет mutable eligibility без переписывания исторических фактов, suspension/deletion блокируют tokens. |
| UI сохранял второй in-app repository selection после GitHub selection. | Было два расходящихся источника выбора: GitHub разрешал repository, но приложение могло его не подключить или держать удалённый repository. | GitHub является единственным местом all/selected repository choice. После полной discovery все выбранные repositories подключаются атомарно; дальнейшие изменения приходят lifecycle reconciliation. |
| Не была проведена граница global App secrets. | Private key, client secret или webhook secret могли оказаться в tenant storage, browser DTO, journal, task payload или diagnostic log. | Все три значения объявлены operator-only secrets и запрещены в tenant storage/browser/journal/task/log. Callback route исключён из nginx access log; secret-bearing ошибки редактируются. |
| Worker credential contract допускал выдачу shared private key. | Компрометация worker открывала весь App и все tenants, а не одну lease/repository. | Control plane сам чеканит/обновляет short-lived installation token по active lease. Worker получает только scoped token; optional repository/permission downscope нормативен. |
| Protected external worker protocol был описан слишком общо. | Не были определены scope команд, credential выдача, fencing после completion и malicious cross-tenant reports. | Protocol аутентифицирован, task/tenant/repo/command scoped, lease-token fenced; completed task закрыт для credentials/reports/renew/release, а exact report replay идемпотентен. |
| Lease renewal, fencing, backoff и `SIGTERM` не были сведены в единый runtime contract. | Потерявший lease worker мог продолжить GitHub/git/Codex I/O или завершить чужую попытку; restart создавал storm либо бросал task. | Renewal происходит до половины lease; failure abort-ит все leaf I/O и запрещает completion; idle wait и bounded jitter backoff обязательны; SIGTERM прекращает claim и завершает либо безопасно освобождает task. |
| Codex subprocess environment и конкуренция не были ограничены. | Агент мог унаследовать `WORKER_TOKEN`, master/auth secrets или глобальный model key; общий `CODEX_HOME` повреждал auth и параллельные runs. | Явный env allowlist, отдельный persistent tenant `CODEX_HOME` и process/file agent lock с heartbeat/stale recovery стали нормативными. |
| Реальный git retry не имел стабильной ветки и fencing remote head. | Crash после push создавал новую ветку/PR или force-push мог затереть чужое изменение. | Stable branch выводится из task idempotency key; retry продолжает existing remote branch, push использует expected-head force-with-lease, PR create сначала reconciles existing head branch. |
| Production topology, durability и health были недостаточно конкретны. | Зелёный in-process harness не означал запускаемый продукт; restart терял state/auth, а readiness не доказывал worker protocol. | Docker Compose, отдельные web/Convex/worker services, persistent Convex и `CODEX_HOME` volumes, tmp workspaces, liveness/readiness и restart persistence закреплены как release contract. |
| Same-origin boundary не перечислял реальные маршруты. | Auth cookies, Convex WebSocket, API calls, webhook или GitHub callback уходили на разные origins/ports и ломались только в браузере. | Nginx обязан маршрутизировать auth, Convex HTTP/API/WebSocket, webhook и App callbacks под одним application origin, сохраняя upgrade/raw body/forwarded headers. |
| Public URL contract не связывал `CONVEX_SITE_URL`, Better Auth и callback URLs. | Generated auth/callback links указывали на внутренний port или неверный host; ngrok показывал interstitial вместо приложения. | Public URLs, `CONVEX_SITE_URL`, allowed origin и GitHub callback URLs должны описывать один внешний HTTPS origin; ngrok smoke передаёт только browser-warning bypass header. |
| Секретное логирование не было явно запрещено по каждому boundary. | URL callback мог записать code/state в nginx, git remote/error мог раскрыть token, protocol diagnostics — lease/global secret. | Нормы требуют `location /github/app/ { access_log off; }`, redaction и отсутствие private key/client secret/webhook secret/user token/installation token/state/code в logs и evidence. |

## Дефекты реализации

| Дефект | Последствие | Требуемое исправление по новым спекам |
|---|---|---|
| Первая production реализация сохранила manual credential form и отдельную mutation repository selection. | Она реализовала старый текст буквально, но не безопасный onboarding и не реальный GitHub UX. | Удалить tenant credential inputs и второй checkbox flow; оставить одну install link и GitHub-selected repository projection. |
| Manifest intermediate хранил/generated per-tenant private key и webhook secret. | Secrets размножались и попадали в tenant encryption/storage path; shared operator boundary отсутствовал. | Удалить Manifest conversion из onboarding и читать shared App credentials только из operator env. |
| Install callback финализировал installation по state+session+App JWT без user OAuth proof. | Атакующий мог подставить существующий installation ID, если получил валидный flow/session context; membership текущего GitHub user не доказывалась. | Всегда продолжать отдельным OAuth+PKCE flow и сверять fully paginated `/user/installations`. |
| Worker чеканил installation JWT/token локально из полученного private key. | Worker обладал deployment-global authority и мог выпускать tokens для любой installation. | Перенести mint/refresh в protected control plane; worker получает только lease/repo-scoped installation token. |
| Lookup завершался report-ом, а merge/close мог потеряться как отдельная task или новый claim. | Между evidence и effect появлялось окно crash/replay; stable idempotency и lease fencing разрывались. | Lookup terminal report атомарно превращает ту же durable task в continuation; worker исполняет merge/close до immediate completion той же lease. |
| Immediate completion acceptance ожидал либо допускал лишний claim перед `complete`. | Worker мог взять следующую task до фиксации результата предыдущей, ломая sequencing и создавая повтор после crash. | Один `runWorkerOnce` делает ровно claim → task/continuations → complete; следующий claim возможен только в следующем вызове. |
| Lease renewal failure первоначально не останавливал уже идущий leaf I/O. | Worker после потери ownership продолжал GitHub/git/Codex и мог записать внешний эффект без права completion. | AbortSignal lease fence передаётся во все phases; renewal rejection abort-ит работу и не вызывает complete. |
| Codex получал inherited process env. | Агент видел control-plane/auth/encryption secrets и не относящиеся к tenant credentials. | Строить subprocess env с allowlist и явным tenant `CODEX_HOME`. |
| Git retry создавал ветку заново и не продолжал remote branch. | Повтор после частичного успеха падал или создавал второй результат. | Обнаруживать stable remote branch, switch/fetch её, сохранять upstream и push с force-with-lease. |
| Nginx сначала не проксировал все same-origin auth/API/WebSocket/webhook/callback пути. | SPA открывалась, но session, subscriptions или callbacks не работали end-to-end. | Явные location blocks и WebSocket upgrade; App callback access log off. |
| `CONVEX_SITE_URL` был направлен не на внешний site/auth origin. | Better Auth и generated URLs использовали неправильный адрес. | Выравнять `CONVEX_SITE_URL` с public application origin и proxy routes. |
| Ограничения Convex на module paths и имена с underscore проявились вокруг `worker_protocol`, `github_app_manifest` и image rewrite `control-plane` → `control_plane`. | Codegen/deploy или production image не находили function references; локальный source и image различались из-за ad-hoc rewrite. | Выбрать допустимые Convex module paths и использовать их последовательно в source, generated references и image. Runtime rewrite имени файла является временным симптомом, а не архитектурой. |
| Ошибка production image исправлялась в source, но запуск продолжал старый образ. | Проверка сообщала старый failure и уводила диагностику в неверную сторону. | Release smoke всегда делает clean rebuild; доказательство относится к digest, построенному из текущего tree. |

## Пробелы проверки

| Пробел | Последствие | Новое требование к проверке |
|---|---|---|
| Vertical/browser acceptance проверял manual App credentials и in-app repository checkbox. | Зелёный тест закреплял неправильный product contract и мешал перейти к shared App. | Browser acceptance кликает одну install link; boundary integration моделирует install/OAuth callbacks; repositories появляются из GitHub selection. |
| Не было negative callback matrix. | Same-session, TTL, one-time use, wrong tenant, swapped installation ID, partial pagination и replay оставались непроверенными. | Добавить строки на все перечисленные отказы, atomic rollback и exact idempotent retry. |
| Не проверялись PKCE и независимость двух state. | Реализация могла переиспользовать install state для OAuth или обменять code без verifier. | Capture authorization URL/token exchange и доказать fresh OAuth state, S256 challenge, matching verifier и one-time consumption. |
| Pagination проверялась happy-path одной страницей. | Installation или selected repository после первой страницы терялись; partial discovery ошибочно считался полным. | Multi-page fixtures для `/user/installations` и repositories; page-limit/upstream failure не создаёт connection facts. |
| Branch-protection permission не проверялся real smoke. | App подключался, но каждый sweep блокировался forbidden lookup. | Smoke читает protected branch required checks реальным installation token и подтверждает administration read. |
| Shared App lifecycle и repository updates не имели acceptance. | Удалённый repository оставался активным, suspended installation продолжала выдавать credentials. | Signed lifecycle deliveries запускают reconciliation; added/removed repos меняют projection; suspended/deleted installation запрещает token mint. |
| Worker protocol тестировал transport auth, но не всю authorization/fencing матрицу. | Валидный worker credential мог отправить cross-tenant command, conflicting replay или использовать completed lease. | Probe связывает effect, tenant, repo, report type/id/payload; проверяет exact replay, conflict, completion fence и отсутствие journal mutation при отказе. |
| Lease loop проверялся без реального abort leaf operation. | Renewal мог падать, но GitHub/git/Codex продолжали выполняться. | Latch probe доказывает abort активной операции и отсутствие complete после fence failure; отдельно проверяются backoff bounds/jitter и SIGTERM release/drain. |
| Real-git integration не проверял retry существующей ветки. | Happy-path clone/commit/push был зелёным, crash-after-push оставался опасным. | Временный bare remote проходит второй prepare/push с тем же idempotency key и тем же remote head/upstream. |
| Runtime checks не доказывали Compose persistence и route wiring. | Отдельные health endpoints были зелёными, но restart терял данные или browser не мог открыть WebSocket/callback. | Integration/release smoke поднимает Compose, проверяет volumes, readiness, same-origin auth/API/WebSocket/webhook/callback и restart state. |
| Clean rebuild не был частью smoke. | Stale image скрывал исправления и создавал ложные результаты. | `compose up --build`/эквивалентный clean build обязателен перед credentialed smoke; evidence фиксирует текущий image digest/source revision. |
| Ngrok interstitial не учитывался browser automation. | Smoke останавливался до приложения, хотя public route был исправен. | Для `*.ngrok-free.app` browser context задаёт warning-bypass header; это не отменяет HTTPS, GitHub auth или callback checks. |
| Release smoke требовал destructively usable credentials, но их доступность не была организована. | Реальный smoke нельзя было запустить; implementation session либо ложно объявляла готовность, либо подменяла GitHub прямыми API/setup mutations. | Отсутствие disposable repository, public HTTPS, Codex credential и authenticated GitHub browser state/interactive approval объявлено blocker. Smoke хранит только evidence, не secrets. |
| Старый manual smoke contract требовал tenant App ID/private key/webhook secret и прямой repository selection. | Он проверял обход настоящего onboarding и поощрял передачу deployment-global secrets тестовому браузеру/процессу. | Smoke использует operator-configured shared App, кликает реальный connect, проходит GitHub install/OAuth и не принимает tenant App credentials. |
| Не было операционного smoke для bootstrap/rotation. | Даже корректный tenant flow не доказывал, что deployment можно впервые настроить или безопасно ротировать. | Отдельная operator runbook/probe валидирует регистрацию App, callback/webhook URLs, permissions/events, key/client/webhook rotation и отсутствие tenant rewrites. |
| Secret redaction проверялась только по journal. | Секреты могли утечь через browser DTO, task rows, nginx/app/worker logs, errors или smoke evidence. | Canary secrets проверяются по всем storage/DTO/log/evidence surfaces; callback code/state и installation tokens тоже считаются чувствительными. |

## Почему прежняя готовность была ложной

Первичная модель хорошо описывала доменные решения admission, evidence, merge и close, но
слишком рано объявила infrastructure boundaries «деталями реализации». На практике именно там
находились authority и durability: кто имеет App private key, как installation доказывается,
когда snapshot становится неизменяемым, что означает потеря lease и какой browser route
считается production.

Поэтому зелёные domain/vertical tests не могли компенсировать неверный onboarding, слабый
worker credential boundary или непройденный destructive smoke. Новые документы сохраняют
существующие доменные факты и язык, но делают явными security, task, browser и operator seams,
которые обязаны быть доказаны до release.
