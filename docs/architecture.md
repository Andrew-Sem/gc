# Архитектура

Event-driven control plane над жизненным циклом PR. Один процесс, один файл SQLite,
server-rendered HTML.

## Пакеты

| Пакет | Ответственность |
|---|---|
| `internal/domain` | Чистое ядро: словарь фактов, `Decide`, `Evolve`. Не знает про SQLite, GitHub и HTTP. |
| `internal/github` | Формат GitHub: разбор вебхуков в команды, разбор ответов API. |
| `internal/store` | Журнал, очередь задач и настройки в SQLite. |
| `internal/web` | HTTP: страницы админки, формы, фрагменты htmx, путь вебхука. |
| `internal/agent` | Запуск Codex, рабочие копии, `git`, создание PR. |
| `internal/app` | Сборка: планировщик, исполнитель задач, порты, старт и остановка. |
| `cmd/gc` | `main`: читает env, собирает `internal/app`, запускает. |

## Поток

```
GitHub ──вебхуки──▶ HTTP ──▶ журнал ──задача──▶ исполнитель ──▶ Codex ──▶ API модели
                     ▲          │  ▲                  │
                  админка ──────┘  └────результат─────┘
```

## Инварианты

- Журнал append-only и единственный источник правды; доменное состояние — его свёртка.
- Секреты живут только в окружении: ни в журнале, ни в задачах, ни в HTML, ни в логах.
- Домен не читает часы: время приходит командой `TickProduction` или `TickSweep`.
- `Decide` не возвращает эффект «разбуди меня в момент T»; расписание держит планировщик.
- Факты и порождённая ими задача пишутся одной транзакцией.
- Очередь читается через интерфейс, исполнитель задач не ходит в базу напрямую.
- Полнота evidence принадлежит свипу: полный снимок или `LookupIncomplete`, не оба.
- Подпись вебхука проверяется до dedupe и разбора.

## Стек

| Слой | Выбор |
|---|---|
| Язык, сборка, тесты | Go, стандартный `testing` |
| HTTP | `net/http` |
| Шаблоны | `html/template` |
| Интерактивность | htmx, без сборки фронтенда |
| Хранилище | SQLite |
| Агент | Codex как подпроцесс |
